Current priority (2026-10-13): screen whether pruning impairs skill composition
beyond constituent-skill loss, then test localized support and mitigation.
Organization predicting independently pruned specialist frontiers remains a
secondary candidate. Neither contribution is established; project decisions live
in [research_strategy.md](../research_strategy.md).
The framework implements baseline quality, component discovery/causal probes,
independent target-calibrated Wanda frontiers and organization diagnostics.
Offline tests validate engineering behavior and provide no evidence for the hypothesis.
Local reviews: [novelty](../composition_novelty_review_2026-10-13.md) and
[tasks/precision](../composition_validation_plan.md). Compression-sensitive multi-hop
reasoning and extra compositional circuit support already have close precedents;

Current dataset design: [composition_benchmark_design.md](../composition_benchmark_design.md).
The station-count/affine v1/v2 datasets below are engineering exercises; the first
research feasibility candidate is now controlled lookup→lookup.

cuts a block. Test choices remain locked to validation configuration and data/code hashes.

**eight primary reference cases**). This is competence/runtime only. Pin/cache the

pruner. Baseline run names end in `_dense`; every retry needs a fresh name/directory.

## Historical station-count exercise

### Original composition contract

**First task family:** factual retrieval A followed by simple arithmetic B, with
linked A, B and A→B cases. Start with one family and add a second composition family
only after baseline feasibility. Code execution and many language targets are not
prerequisites. `count_affine_v2` implements the context-supplied track and numeric-fact
import. Qwen2.5-7B-Instruct is the server candidate; its immutable revision and
pretrained feasibility remain to be established in Phase 2.

- Each case has an episode ID, source/fact group, split, task variant, gold
  intermediate, final answer and difficulty/template metadata. Use existing record
  metadata first; a new schema or evaluator is added only if necessary.
- A retrieves the needed fact; B computes from the correct provided intermediate;
  A→B requires both in one task. Add a composed-prompt variant with the correct
  intermediate supplied and a staged A-then-B evaluation to measure error propagation.
- Controlled context-supplied facts test knowledge use/computation. A separate
  parametric-recall track is needed for claims about stored factual knowledge;
  do not pool these tracks or interpret the former as locating factual storage.
- Split by underlying case/source/fact groups before creating variants. All linked
  variants stay together. Reserve new combinations/templates when claiming that
  composition generalizes. Exact-input checks alone cannot enforce this isolation.
- Synthetic fixtures only validate engineering. Choose meaningful research data,
  prompt format and any eligibility rules on discovery/validation; never select
  test cases using post-pruning success. Report the full cohort; if a baseline-correct
  subset is analyzed, label it explicitly and report its size/selection rule.

**Readout:** deterministic normalized short-answer accuracy for each variant,
paired changes from the unpruned model, and episode-clustered uncertainty. Handle
malformed/absent answers explicitly. Likelihood can be secondary; it cannot replace
behavioral performance for the central claim. Do not assume P(A)×P(B) predicts
composed accuracy: errors are dependent. Compare observed staged/oracle controls.

Implemented parser: one signed integer (≤18 digits), whitespace and optional terminal
period. Explanations, units, decimals and multiple numbers are malformed. Greedy
generation uses native chat or explicit plain formatting, left padding and no context
truncation. Staged B receives the actual parsed A output, including wrong integers;
malformed A fails the staged case without a B call. All cases remain in the cohort.
Staged calls and the oracle supply extra computation/information. They diagnose a
failure stage, not equal-inference-cost alternatives or proof of a neural mechanism.

**First GPU screen:** one pretrained 7–8B model, unpruned baseline plus a small
validation-fixed Wanda grid. Use the same cases and fixed prompts at each budget.
Compare target-composition and mixed A/B/composition calibration at equal token
budgets and repeat calibration seeds. Fix tolerable constituent loss and a meaningful
extra composition effect on validation before test; report per-variant precision.
Prompt length, difficulty, formatting and baseline floor/ceiling are confounders.
If the full model cannot do A→B reliably, revise the task/model before interpreting
pruning. This screen establishes feasibility, not unseen-target prediction.

### Build, preflight and server handoff

```powershell
python experiments/icml2027/build_composition_data.py --output-dir results/composition_data_v2 --episodes-per-split 128 --seed 2027
python experiments/icml2027/run_composition_screen.py --config configs/experiments/icml2027/composition_screen.json --validate-only
```

Already built locally: 384 cases / 1536 records, 128 cases per split. The
v2 dataset shuffles target identity/context order, samples independent distractor
counts and explicitly requests only the composed final answer. v1 is preserved.
The exclusive dataset folder has a manifest/summary; results/data are not committed. Regenerate on
the server or transfer the exact file and check SHA-256. Existing directories are
rejected; use a fresh name and update the config when rebuilding.
`--facts <jsonl>` imports `id`, `source_group_id`, `fact_group_id`, `question`, integer
string `answer`, `knowledge_scope`, `source_name`, `license`. Context-supplied imports
require `context`; parametric imports forbid it. Repeated facts/aliases share a source
group. Generated cases are controlled stimuli, not evidence of real-domain transfer.

The server config starts with 32 validation cases, four retained fractions, two
calibration modes and three seeds. Each mode uses exactly 4096 non-padding discovery
prompt tokens; an explicitly logged last-prompt prefix fills the budget. No output
targets or oracle variants enter calibration; B's given intermediate is part of its
task input. Token availability is checked at execution. Calibration seeds are repeated
conditions, not extra independent examples. Source-group bootstrap intervals are
exploratory/pointwise and unadjusted across conditions.

Candidate thresholds: dense A/B/composed accuracy ≥0.70, constituent loss ≤0.05,
composed-minus-staged damage ≥0.10. Flags use point estimates, **not statistical GO**.
Thirty-two cases check feasibility, not power. Assess size/precision and prompt controls
on validation before confirmation; no automatic negative conclusion is produced.
The [precision review](../composition_validation_plan.md) includes a local calculator,
512–2048-case scenarios and remaining confirmation-analysis requirements. No test
protocol is scientifically ready just because its settings can be locked.

Pin config `revision` to a 40-digit model commit, cache weights and choose a fresh
experiment name, then remove `--validate-only`. Unpinned research execution is rejected;
downloads default off. Outputs include manifest/config, selected IDs, `decisions.csv`,
calibration ledgers/pruning reports, `metrics.json`, protocol candidate and summary.
Timing, CUDA peak, nonzeros, dense storage and CPU restoration-backup bytes are separate.
Recorded timing is diagnostic, not evidence of sparse speedup or physical VRAM savings.

After validation choices, use `--freeze-protocol <fresh-json-path>` instead of running
inference. A test config sets `split=test`, that `test_protocol_path` and a fresh run name.
Dataset hash, semantic settings (including cohort cap) and relevant implementation
hashes must match. The lock preserves choices; it does not certify scientific readiness.
`--validate-only` audits all split/group boundaries without model loading or run creation.

**After a promising screen:** localize support with discovery-only head/MLP-group
interventions. Test targeted retention/restoration against random, layer/cost-matched,
singleton/activation and appropriate interaction-aware controls. Keep original
causal measurements separate from independent Wanda outcomes. Restoration must
be compared at equal actual retained capacity; count any dense source checkpoint.
The current code cannot yet perform targeted restoration in a Wanda-pruned model.
Do not call selected components "bridges" without intervention evidence; an oracle
intermediate alone diagnoses a failure stage, not a neural mechanism.

**Scale-up gate:** a precise effect beyond constituent errors and the above controls,
an identifiable contribution beyond PRISM/Compressed Lens, Circuit Claims,
Circuit Compositions/CircuitLoRA/CoAx/ProxySPEX, and a
credible held-out mitigation or mechanistic result. Then test another model/pruner
and new task combinations. A null p-value or a pretty map is insufficient.

## Run and inspect

```powershell
python experiments/icml2027/run_target_baseline.py --config configs/experiments/icml2027/target_baseline.json --validate-only
python experiments/icml2027/run_target_baseline.py --config configs/experiments/icml2027/target_baseline.json
```

Only the first command was checked on the local MMLU dataset during development.
The second loads a model and evaluates it. The example uses TinyLlama, CPU,
10 sampled validation records per domain and cached weights; this is a small
engineering configuration, not the planned 7–8B scientific pilot.

Config fields are validated, including unknown/misspelled keys. Dataset paths
are relative to the config file. Set `target.field` to `domain`, `language`,
`capability` or `task`, and `target.value` to an explicit dataset label. All
values of that field on the configured split are evaluated, so target and
non-target measurements come from the same run. Missing labels fail validation.
Old MC records still load for domain evaluation; missing languages are not
inferred. QA records also support the target abstraction, but this runner
evaluates MC only. Math/code generation tasks need separate evaluators.

Set `revision` to an immutable model commit for research runs. Both tokenizer
and model receive it. `local_files_only` defaults to true; downloading requires
an explicit false value. `max_records_per_value` may be null to use the whole
chosen split. Capped samples are seeded, drawn from ID-sorted records, and saved
by ID. Seeded selection does not promise bit-identical GPU inference.

Results go to `results/<experiment_name>/`, or `--results-root`. Existing folders,
including empty or failed runs, are rejected before model loading. Retry with a
new name. A run writes:

- `config.json`: resolved configuration.
- `manifest.json`: commit/dirty flag, versions, seed, input SHA-256, requested and
  resolved model revision (null when unavailable), actual device/dtype, evaluation
  definitions/counts and running/complete/failed status.
- `evaluation_records.json`: selected IDs, split, field/value and source.
- `candidate_scores.csv`, `decisions.csv`: detailed MC results using the legacy
  column schema, joined to target labels through selected record IDs.
- `metrics.json`: accuracy, correct-answer loss and margin per target-field value.
- `summary.md`: at most 40 lines; failures retain their error in the manifest.

## Measurement and split policy

Candidate scores and decisions reuse the existing MC evaluator without changing
the metric definitions. Prediction uses the highest **mean token log-probability**,
with choice order breaking ties. Accuracy weights examples equally; correct loss
is the mean negative token log-probability of the correct continuation; margin is
correct minus best incorrect mean token log-probability. `choice_text` and `letter`
are distinct protocols and must not be pooled without justification.

The complete dataset is audited before split filtering or sampling. Duplicate
IDs and normalized inputs shared across discovery/validation/test are rejected.
For MC, identity includes the question and the multiset of normalized options,
so reordered options cannot hide reuse and generic question stems alone do not
trigger errors. This does not detect paraphrases, shared facts, translated
equivalents or overlap in source passages; those need source-level audits.

Use discovery for component measurement/selection, validation to fix choices,
and test for the frozen final protocol. Passing this baseline preflight does not
enforce that later experiment decisions respected those roles.

`prompt_policy` explicitly selects legacy, plain base-model or native tokenizer
chat formatting; example configs use the native template. Instructions remain
English and prompt quality/multilingual controls still need scientific validation.
No conclusions about causal importance,
compressibility or multilingual competence follow from the offline random-init
tests or the example config.
