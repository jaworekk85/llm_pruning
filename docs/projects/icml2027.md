## Active candidate

Separate families: `lookup_lookup` primary, `lookup_add` secondary.
Use `composition_lookup_screen.json` / `composition_add_screen.json` under
`configs/experiments/icml2027/`. `composition_screen.json` and station-count
v1/v2 are engineering exercises. None establishes the hypothesis.

A/B/composed/oracle share evidence; staged B receives the model's actual parsed
A answer, including wrong integers. Malformed A fails the staged case without
a B call. Every case stays in the readout. The parser accepts one signed integer
(≤18 digits), whitespace and an optional terminal period; no explanations/units.
Generation is greedy, with context-overflow checks and no silent truncation.
Staged/oracle gains include extra computation/information, not a neural explanation.

Source-group caps retain all reference/target/distractor/order/name episodes.
Primary metrics use reference cases only; probe roles are separate.
First default cap: 8 groups / 40 role episodes, only 8 primary cases.
Dense competence and probe behavior must pass validation review before pruning.

## Calibration, outputs and confirmation boundary

Discovery calibration uses reference prompts only: composed or mixed A/B/composed.
Each condition has exactly 4096 non-padding prompt tokens, with a logged final
prefix when needed. No oracle/probe/output targets enter calibration. B's supplied
intermediate is task input. Calibration seeds are repeated conditions, not cases.
The template grid is retained fractions [1,.9,.75,.5] and seeds [11,23,37];
scope/cost review precedes a full grid.

Research execution requires a pinned 40-hex revision. Native chat policy, dataset
SHA, selected IDs, model revision/device/dtype, versions, calibration ledgers,
`decisions.csv`, `metrics.json`, protocol candidate and compact summary are recorded.
Existing result directories are rejected, including failed/empty ones.
`--baseline-only` evaluates one dense condition; `--validate-only` loads no model.

Bootstrap intervals are exploratory, pointwise and unadjusted. Candidate flags
(.90 dense competence, .05 constituent damage, .10 extra loss) use point estimates,
not a statistical GO. Review the validation plan before scientific confirmation.
`--freeze-protocol <fresh-json>` binds data, semantic config and implementation
hashes; test needs `split=test`, that lock and a fresh experiment name.
The lock preserves choices; it does not certify readiness. Confirmation analysis
and multiplicity/sample-size choices must be implemented/fixed before test.

Report nonzeros, dense tensor storage, timing, CUDA peak and CPU restoration backup
separately. Current masks do not demonstrate physical memory/latency savings.
Targeted restoration, held-out neural mechanism tests and model/pruner transfer
remain future work. Context tasks do not locate stored world facts.
